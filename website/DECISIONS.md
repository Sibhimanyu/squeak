# Decisions

Assumptions made while building, after the plan was approved.

## Structure
- **One DOM for every width.** The four example states ("The moment") are four `li.beat` elements, each with its own copy and a small HTML replica of the Mac window. Without script, on narrow screens and with reduced motion they simply stack. On desktop, `motion.js` adds `html.js-pin`, which layers them in one grid cell and crossfades their children on a scrubbed, pinned timeline. Nothing is hidden by CSS unless that class is present.
- **The pinned element is `.moment__pin`**, whose ancestors carry no transform, filter or contain. The pin runs 175% of the viewport; pin spacing is ScrollTrigger's own.
- **Pin query:** width ≥ 900px, height ≥ 620px, motion allowed. Tablet (768–899) gets the stacked layout.
- **The example is non-interactive.** No control pretends to send anything. Beat 3 says "A person chooses A" and "Example only. Nothing is sent." The only button is "Replay example", which scrolls to the start of the pin when pressed.
- **Demo panels are `aria-hidden`**; each beat's heading and paragraph carry the whole story, including the question and options.

## Content
- **Release metadata comes from `release.json`** (version, file name, download URL, minimum macOS), imported in `content.ts`, so the page cannot drift from the build tooling. It currently says 2.1.11 (an earlier draft hard-coded 2.1.9 from a stale local appcast). Structured data (JSON-LD) is generated by the build, not the template.
- **"Apple silicon"** is accurate: the Mac app is built with `swift build -c release --arch arm64` (`macos/scripts/build-app.sh`) and `macos/scripts/release.sh` labels releases macOS 14+ / Apple silicon.
- **No SHA-256 line**, to keep install short; `release.json` holds one if wanted.
- **Compatibility** follows CLAUDE.md: Conductor and claude/codex in Apple's Terminal can be answered; other local terminals (no claim about remote or ssh sessions), Claude Desktop (Code and Cowork) and the Codex app are watch-only. Cowork's "cannot report an approval prompt" is stated.
- **iPhone link** points at the SideStore page (`squeak-5c9gvo.web.app`). The source repository is private, so it is not linked; "All releases" keeps the existing releases URL.
- **Example consistency.** The hero, the pinned example, the Mac screenshot and the Telegram card all use `storefront · payment-retries`. The iPhone capture is a real screenshot of a different session (`squeak · session-hub`), so its caption describes the feature ("a working turn"), not the example. `duck-panel.webp` is not used: it shows a different example (`orchard · checkout-retries`).
- Copy, links and numbers live only in `src/content.ts`; the template has no literal copy except the build-time `{{tokens}}`.

## Visual
- Hero headline 100px at 1440 (clamped from 46px), with a flat Duck Yellow marker behind "In view.". The approved duck art is perched on a dark session panel; the panel is HTML, not an image.
- The demo windows are light (matching the real app) on the one dark Ink stage. The close is a full Duck Yellow section with Ink text; Ink buttons on light, no gradients or glows.
- Status is never colour alone: every dot has its words beside it.
- State dots use DESIGN.md's light-surface tokens (`#DC2626`, `#15803D`) and the dark tokens on the dark panel. Red *text* on light surfaces is the darker `#B91C1C` for AA contrast (see Review round).

## Motion
- Only transform and opacity. Hero entrance is CSS, so nothing waits for script. Below-fold `[data-reveal]` items are hidden by script only if they start below the first screen, so no content is ever hidden without JS.
- Ducks move once as they arrive (working bob, needs-you startle, done hop, asleep settle); no looping.
- The pin is created after fonts load, later than the below-fold triggers, so its trigger has `refreshPriority: 1` and is measured first on every refresh; later triggers then see the pin spacer.
- `ScrollTrigger.refresh()` runs after `document.fonts.ready` and `load`. `gsap.matchMedia` removes the pin, class and listeners on resize or preference change.

## Review round (parent findings)
- **Length:** desktop 7880px (8.76 viewports, was 9.75) with the 175% pin intact. Trust shows three one-line assurances; the long explanations and the compatibility table are in a native `details/summary` (56px target, focus ring, +/− marker). Away keeps two short points. Mac capture max 1080px with a "View full screenshot" link; the callouts stay numbered.
- **Mobile:** 9143px (was 11.8k). In the stacked story the app windows drop their session lists (the state is stated in the detail pane and the copy); moment is 2263px. All four story texts remain in the DOM and visible without JS or with reduced motion. Away puts copy first, a cropped phone capture at 210px and a compact Telegram card.
- **Copy accuracy:** the done mood reads "Celebrates for a short while after a turn really ends."; the table row is "Other local terminals".
- **Contrast:** red text on light surfaces is `#B91C1C` (≥4.9:1); small rail labels `#9A9DA4` on Ink (≥6:1).
- **Pin robustness:** ScrollTrigger id and score beat are both `moment`. The window no longer has a max-height; instead the pin is used only if every state fits (checked after fonts load and on resize), else the stacked layout stays. At 1280×720 and 1024×768 the pin is active and nothing clips. Resize to a narrow width removes `js-pin`, the spacer and listeners; widening restores it.
- **No overlap mid-fade:** old copy leaves before the cut, new copy returns after it, and the old window fades out in the first half of the crossover while the new one arrives in the second.
- No interactive element sits inside an `aria-hidden` region (windows, rail and markers are non-interactive).

## Known trade-offs
- Desktop is 8.76 viewports, inside the 7–9 target. The phone capture is cropped (top 70%), so its composer is not shown.
- The compatibility table is closed by default; it is one tap away and fully readable without JS.

## Lusion pass

> Superseded by the focused hero revision. The page now leads with a quiet
> headline and primary download decision, followed by one real session-panel
> composition. The decorative duck pile, canvas physics and stage expansion
> were removed; a single duck remains as a brand accent on the panel. The
> verifier's hero pass checks that the product panel, textual signal and CTA
> remain present at desktop and mobile sizes.
- **Hero is a compact header block plus an inset Ink stage** (24px radius, frame margins on the page grid, `max(gutter, (100vw - wrap) / 2)`). At 1440x900 the stage starts at 312px and fills the rest of the screen (`.hero` is `min-height: 100svh`, the stage `flex: 1`, never under 420px). The HTML "Sessions" panel floats inside it as the product truth. The big perched hero duck is gone; the pile replaces it.
- **The duck pile is a rule exception, on the planner's brief.** DESIGN.md 6.3 says one duck per screen and never as a pattern; the brief asks for a pile of approved ducks as the one touchable scene. Only existing files are used (`duck-brand.svg` mostly, three mood webps, the needs-you one perched on the panel's top edge beside the "1 needs you" row). Sprites are scaled, rotated and translated only. The webps are 240px, so they are drawn at 82% width to stay sharp at 2x.
- **Physics is `ducks.js` (about 5 KB gzip), no library.** A duck is one rigid body of two or three circles, 120 Hz fixed step, sequential-impulse contacts with friction, low restitution (bounce only above 120 px/s), a small righting torque until a duck rests, walls at the frame, and the panel as a static rectangle. 20 ducks on desktop, 9 under 700px. The loop sleeps when everything is calm, pauses off screen (IntersectionObserver) and in a hidden tab, and wakes on the pointer (push within 120px scaled by pointer speed; a press hops nearby ducks). DPR is capped at 2. The canvas bleeds 24px past the side walls and below the floor so a tail or foot is not cut when the stage goes full-bleed. `data-state`, `data-frames` and `data-awake` on the canvas are read by `verify`.
- **No empty frame, ever.** The same ducks exist as 20 `<img>` elements in `.pile` (the sprite source for the canvas too). They are the whole picture with no script and with reduced motion. A tiny inline head script adds `ducks-pending` (not under reduced motion), which hides the pile only until `ducks.js` takes over; if it never does, a CSS animation shows the pile after 3 s.
- **Stage to moment.** On the pin query only, a scrubbed timeline (`id: "stage"`, 40px to hero-bottom at 35%) tweens the stage's clip-path inset (`--mx`, `--mb`, `--r`) to zero while the header block rises and fades; the marks fade. It ends about 315px before the moment pin starts (585 vs 900 at 1440x900). Nothing above `.moment__pin` carries a transform. The clip-path is the one non-transform, non-opacity animation, as the brief allows.
- **Lenis 1.3.27** is pinned in `package.json` and `assets/vendor/lenis.min.js` (copied from the package, source-map comment removed), 5.4 KB gzip. It runs only when motion is allowed, on the real scroll position, `anchors: true`, driven by the GSAP ticker and feeding `ScrollTrigger.update`. Touch keeps native scrolling. Replay uses `lenis.scrollTo`.
- **Chrome.** Header: logo, two quiet links, dark `Download` pill with a yellow dot (the round icon button was left out: it would have nothing to do). Magnetic pull (6px max, fine pointers, motion allowed) on the primary pills. Kickers are mono uppercase with a `+` and an index (`01 / The moment`). Duck mood cards lift 6px on hover and replay their one-shot mood motion (never while it is still running).
- **Added JS** is Lenis 5.4 KB + `ducks.js` 5.3 KB gzip. Page transfer after a full scroll is about 0.9 MB. Page length is unchanged (7,884px at 1440x900).
- **Verify** gains a "lusion pass" scenario (`npx tsx scripts/verify.ts --only=lusion` runs just that): live canvas, aria-hidden and text alternative, stage within 420px, settle and sleep, pointer wake, CLS, Lenis, anchors, stage expansion ending before the pin, transfer and script weight, mobile canvas, and the static pile with reduced motion and with JS off.

### Lusion pass, review fixes
- **The pile is `duck-brand.svg` only** (26 ducks, scale 0.8-1.15; 10 on narrow screens). The single needs-you duck (`duck-needs_you.webp`) is a separate `data-perch` sprite inside the panel: the physics drops it onto the panel's top edge, and the static picture shows it there too.
- **The Sessions panel is a solid collider** on every width (a duck's bill and tail stick out past its circles, so the rectangle is 20px wider on the left). The canvas now sits under the panel, so a duck can never be drawn over it. Only about 30% of the panel's width is a spawn target, so a few ducks land on its top edge rather than a tower.
- **Desktop stage** is `flex: 1` between 420px and 560px of frame, so the stage top stays at 312px at 1440x900 (checked), and 26 ducks fill the heap.
- **Under 900px** the stage is the panel's height plus 200px: the panel is flush to the frame's sides and bottom, and the heap sits across its full-width top edge (the field now spans the whole frame on every width). The static pile is the same picture, in the 200px above the panel.
