# Code map

Where everything lives. Paths are repo-relative.

- `src/squeak/` — the daemon: config, CLI (`squeak start`, `setup`, `install-hooks`), the Telegram bot
- `src/native/` — native chats: Squeak runs Claude and Codex sessions itself, in the session host (`squeak host`, `com.squeak.host`, 127.0.0.1:8479, `x-squeak-token` = the control token), a process apart from the daemon so `ship.sh` restarting the daemon never kills a running turn; sessions and messages in `native.db` (support dir; the fleet reads it read-only); Claude transcripts carry entrypoint `"squeak"`; Codex defaults to `untrusted` approvals because `on-request` is Codex's Auto preset. Every chat's agent gets Squeak's tools as an MCP server (`agent-tools.ts`: `/mcp/<chat id>` on the host, a per-chat HMAC token from the control token; workspace diff, review comments, notify, progress, target branch, and agent-to-agent `list_chats`/`read_chat`/`send_to_chat`/`start_chat`, rate-limited, a started chat never wider than its parent) and Claude chats get `agent-plugin/` (the `squeak` skill; embed-daemon.sh copies it). `workspace-sources.ts`: workspaces from a branch, a base, a PR or an issue, and clone; `planner.ts`: backlog and routines (never in a mode that skips approvals). `chat-starter.ts`: the one way a chat starts (placement aliases, inherited model, Duck link); it is the only caller of `host.create` for Ducks, so new start paths call `starter.create`/`fromRequest`, never `host.create`. The Claude Agent SDK is Anthropic's (all rights reserved), so the app never ships it: `agent-sdk.ts` (`loadAgentSdk`) uses an installed copy, else `<support dir>/agent-sdk/<version>`, else fetches the tarball pinned in generated `agent-sdk-pin.ts` (sha512 from package-lock.json, `scripts/make-agent-sdk-pin.ts --check`) from npm; `embed-daemon.sh` marks it external and fails if it is inside. The engine is clean-room: no agent reads Conductor's internals or the sealed teardown when working on it (`docs/PROVENANCE.md`)
- `src/native/file-locks.ts` — folder Pond file locks: a Duck editing a folder Pond (no Streams) takes a per-file lock through the runner's `guardEdit` hook (Claude PreToolUse + canUseTool, Codex file-change approval); released at turn end, idle expiry 10 min; a refused Duck is told the holder and to @mention it; the host emits `file-clash`, `attachSqueakPosts` turns it into one `needs` Room line. Git Ponds are never guarded; shell commands are not covered
- `src/core/` — `repository.ts`: `normalizeRemoteUrl` (remote URL to `host/org/repo`), shared by project inference and ponds. The old provider-neutral core and its `core.db` mirror were removed; the daemon deletes a stale `core.db` at start
- `src/flotilla/` — Ponds (docs/ponds.md): on for everyone, `SQUEAK_FLOTILLA=off` is the off switch. Every project is a pond; a **local pond** (`local: true` in `flotilla/ponds.json`) exists only on this Mac, makes no network call and works with no cloud, until the first invite publishes it (`FlotillaService.publish`, once, retry-safe). `ensureLocalPond` never makes a second pond for a project. A member running their own agent on their own Mac (own threads, git-backed) is stashed: off unless `SQUEAK_POND_OWN_THREADS=on` (docs/ponds.md); members start on the owner's Mac. `room-sync.ts` carries a shared pond's Room and Tasks to Members (sealed kinds `room`, `rposts`, `rtasks`; docs/ponds.md, "The Room reaches Members").
- `src/fleet/` — discovers Squeak's own chats. External discovery requires the corresponding add-on in `addons/` (`claude-external`, `codex-external` or `conductor`). All three are off by default
- `src/fleet/observers/` — one file per discovery source (Claude transcripts, Claude Desktop Cowork, Codex rollouts, processes, Squeak native); none of them know about each other. Core runs only the Squeak native one; the rest are driven by the add-ons, and a host app's observer (Conductor's) comes from its add-on
- `src/fleet/fleet-monitor.ts` — merges observers and hook events, decides what needs attention
- `src/fleet/runtime.ts` — assembles the fleet stack; only one process may run it
- `src/fleet/hook-ingress.ts` — loopback HTTP: agent hooks, `/state`, token-gated control routes
- `src/addons.ts`, `src/addon-host.ts` — the add-on contract and the registries core consumes instead of importing any add-on: `AddonManifest` (`addon.json`: id, name, blurb, `distributed`, `requires`), `AddonContext` ({supportDir, config, logger, snapshot(), refresh(), isEnabled(), setEnabled(), services}), `AddonHandle` (observers with `SourceRules`/`watch`/`resolve`, repliers, newChat, workspaceActions, chatModels, projectIcons, routes with `:params`, stateFields, frontApp, cli, uninstall, maintenance, start, stop). `AddonHost` owns `addons.json` (`{ enabled: { [id]: { enabledAt } } }`, absent = all off), `GET/POST /control/addons` (token-gated; strict `{id, enabled}`), `/state.addons`; enabling takes effect on the next refresh. `src/` never imports `addons/` (guard test)
- `src/fleet/hands.ts`, `reply-router.ts` — `runHands` (shared helper that drives Squeak Hands); one replier for every Mac-side surface: host chats through the enabled add-on's `AddonReplier`, terminal agents the other way
- `src/fleet/terminal-reply.ts` — answers a `claude`/`codex` running in Terminal by typing into its tab
- `src/fleet/terminal-process.ts`, `terminal-screen.ts` — proves which process and tty a session is; reads its screen for an empty prompt
- `src/fleet/activity.ts` — a working session's current turn, step by step, for the Mac app's "What it's doing"
- `src/fleet/work-split.ts` — a new chat's work split (iPhone "Split the work"): the chat's model plans, Claude subagents code (`code`) and run commands (`run`) through the Agent tool's `model`, and `planFirst` holds changes until go. Reaches the agent as a short brief in front of the first message, sent as Conductor's `agentMessage` so the chat shows only what was typed (Conductor 0.91.2's runtime hands the agent `agentMessage ?? message`); the relay cannot set plan mode (`/config` refuses it). The Mac lists `chatWorkers` beside `chatModels`, and a phone sends `split` only to a Mac that does. First message only: a long chat's compaction can summarise it away
- `src/fleet/background-work.ts` — a working Claude chat's subagents (Agent/Task; async by default: the launch result says `async_launched`, a `<task-notification>` with its tool-use id and `<status>` ends it) and background shells (`Bash` `run_in_background`), from a 1 MB tail cached by size/mtime; finished ones stay 10 min; the phone view's `background`
- `src/fleet/codex-subagents.ts` — a Codex chat's subagents: each is its own rollout whose `session_meta` names the parent (`source.subagent.thread_spawn.parent_thread_id`, task name in `agent_path`), found by scanning day folders from the parent's day, state from its newest `task_started`/`task_complete`/`turn_aborted`; children stay off the radar as chats; Codex's `exec` tool calls are labelled by the `tools.*` call inside the script (`describeCodexTool`)
- `src/fleet/choices.ts` — reads lettered options out of an agent's last message, for one-tap answers
- `src/fleet/caffeinate.ts` — keeps the Mac awake (`caffeinate -i -w <pid>`) while an agent works, 2 min grace, and (`-s`) always while plugged in so the phone can reach it; `SQUEAK_CAFFEINATE=working` / `off`. an awake session (`awake-session.ts`: the Mac app's menu-bar panel, iPhone Settings; `POST /control/keep-awake`, phone command kind `awake`) holds `-i` on battery too, for a while or until ended, saved in `keep-awake.json`
- `src/fleet/lid-sleep.ts` — lid-closed awake sessions: `sudo -n pmset -a disablesleep 1` through a sudoers rule (`/etc/sudoers.d/squeak`, exactly four pmset commands) the Mac app installs with macOS's admin prompt; journalled in `lid-journal.json` and undone at start
- `src/fleet/power-monitor.ts`, `awake-backstop.ts` — an awake session's safety rules, and the Mac's battery, draw (`ioreg -rn AppleSmartBattery`; a discharge prints as an unsigned 64-bit amperage) and lid for the phone's `macPower` (battery via `pmset -g batt`, heat via `notifyutil -g com.apple.system.thermalpressurelevel`, no root): Low Power Mode at 40% or when hot, end at 10% or critically hot (`SQUEAK_AWAKE_LOW_POWER_PERCENT` / `_END_PERCENT`); the effective floors reach surfaces as `awakeRules` in `/state` and the phone view, and a surface says 40/10 only when it is absent; and `com.squeak.awake-backstop`, a launchd agent the daemon installs once the sudoers rule is in, which undoes a journalled change when the daemon is gone or the session's end passed 2 min ago
- `src/fleet/lid-actions.ts` — when the lid shuts during a lid session (ioreg every 5 s): display off (`pmset displaysleepnow`), mute (only if not muted already), Low Power Mode (through the session), and optionally SIGSTOP to Slack/WhatsApp/Discord/Telegram; journalled in `lid-actions.json`, undone on open, at start, and by the backstop when the daemon is gone; settings in `awake-settings.json`; a phone changes them with the signed `lidActions` command (strict booleans, same `applyAwake` path), and the phone view carries `awakeLidActions`. Two modes, each with its own saved switches: lid closed (the above, kept at the top level of `awake-settings.json` for older versions) and lid open (`open`: screenOn = a `caffeinate -d` child that dies with the daemon, mute, lowPower, freezeApps; all off by default), which applies whenever a session runs with the lid open, so a lid-closed session runs the open switches until the lid shuts and again after it opens. `lidActions` takes `mode: "open"` (absent = closed, keys checked per mode); the view and `/state` carry `awakeOpenActions`, whose presence is how a phone or the Mac app knows to show the Lid open / Lid closed tabs; the journal records which mode wrote it, and an open-mode journal is undone at start, never taken over
- `src/fleet/heat.ts` — heat during an awake session, read every 15 s: the hottest die sensor and the fans from `helpers/squeak-fans` (`read`, IOHIDEventSystemClient and the SMC, no root; the Mac app bundles it in `Contents/Helpers`), the battery from AppleSmartBattery. macOS's thermal pressure says "serious" only once the chip throttles, and in a bag the hinge vents move little air, so it acts earlier and on making less heat: warm (battery ≥ 40 °C, or the die ≥ 90 °C with the lid shut, two looks) is Low Power Mode, every `claude`/`codex` process and its children moved to the efficiency cores (`taskpolicy -b`, no root), and fans to full; a minute under 37/80 undoes it; hot (battery ≥ 45 or die ≥ 105) is told at once and two minutes of it end the session. Fans move only through the root-owned copy at `/Library/PrivilegedHelperTools/com.squeak.fans` and `/etc/sudoers.d/squeak-fans` (exactly `max`, `80`, `60`, `40`, `auto`: fixed settings, never an open-ended speed), which the Mac app installs with one admin prompt after checking the bundled helper carries its own Team ID. Journalled in `heat-journal.json`, undone at start, at stop, and by the awake backstop when the daemon is gone; `/state` and the phone view carry it (`heat`, `macHeat`)
- `src/fleet/mac-controls.ts` — the phone's Mac controls page (Settings › Mac controls): volume and mute (`osascript` `set volume`), the built-in display's brightness (`squeak-fans brightness N`, DisplayServices, no root, lid open only), the fans (through `HeatGovernor.setFanChoice`, so heat still raises them to full and they go back to the pick when it cools; the pick lasts until changed or Squeak stops) and screen off (`pmset displaysleepnow`); apps through `helpers/squeak-apps` (no permission: the running ones in the view, the installed list only in the answer to `listApps`, opened with `open -b` only if installed or running, quit only if running, by `NSRunningApplication.terminate()`); desktops, media keys and lock through Squeak Hands' `system-key` mode, six fixed actions, since posting keys needs its Accessibility grant. The front app's tabs (`window-tabs.ts`, on demand: `listTabs`, `selectTab`, `showChat`): Conductor's recent workspaces and open chats from its records, opened by Squeak Hands' `show-chat` (the same `openChat` as replies and close: sidebar route, then the tab whose route names the session); any other app's front-window tabs through Hands' `tabs` mode (Safari/Chrome `AXTabButton`, Terminal/Finder radio buttons in an `AXTabGroup`, never inside an `AXWebArea`; Chromium needs `AXEnhancedUserInterface`/`AXManualAccessibility` set), pressed only while the tab at that index still has the title the phone saw. energy mode (`power-mode.ts`: `auto`/`low`/`high` = `pmset -a powermode 0/1/2`, read from `pmset -g`, offered only as `pmset -g cap` lists it, so High Power only on some Macs; its own sudoers file `/etc/sudoers.d/squeak-power`, exactly those three commands, installed by the Mac app (Settings › Keep awake › Energy mode, `GET /control/power/rule`); the pick lives in `power-mode.json`, and heat/safety Low Power wins over it through `LidSleepGuard` (journal `restorePower`, undone by the backstop too) and the pick returns after). Signed command kind `controls` with exactly one key and an exact value (`readControlChange`); the phone view carries `macControls`, refreshed every 15 s while a phone looks. It ranks the running apps itself (front, then most recently front, at most 6), says `media.playing` from `pmset -g assertions` (coreaudiod's `audio-out` assertion, no permission) so the page shows media keys only while sound plays, and collapses a burst of volume/brightness writes to the newest value; the phone's sliders are local-first, ~150 ms live cadence, and ignore a stale reading for 2 s
- `src/squeak/flags.ts` — the feature-flag registry: name, env var, default, stage; `flag(name)` reads the env with each switch's old parsing, an optional `flags.json` in the support dir overrides for staged rollout (env wins, read once at start, bad file ignored); read-only `GET /control/flags` (token-gated). `docs/flags.md`
- `src/fleet/notify-settings.ts` — what Telegram and Cliq may push, per channel (`notify-settings.json`: `muted`, `approval`, `question`, `stalled`, `quota`, `finished` conductor/all/off, `quiet` hours that hold back finishes, questions and stalls but never a blocked approval); `shouldPushTo` narrows `shouldPush` (defaults = today), applied in each channel's own push path (`FleetController`, `CliqChannel`) so the radar and apps keep every card; `GET/POST /control/notify`, the phone view's `notify` and the signed `notify` command (docs/remote-channel.md, "Notification settings") end in one `applyNotify`
- `src/fleet/hotspot.ts` — hotspot failover: when the internet is gone ~30 s during an awake session or while an agent works, join the iPhone's Personal Hotspot through Squeak Hands (CoreWLAN scan by name, then associate, one retry; it needs Location Services, since `networksetup -setairportnetwork` cannot find a hotspot on macOS 26), and back by Wi-Fi off/on. iOS advertises the hotspot only while its Personal Hotspot screen is open or a device is on it, so most real tries were `not-found`. A failed try is told when the Mac is back online, never while offline, where Telegram and Cliq could not carry it. macOS 26 redacts every Wi-Fi name from command-line tools, so "on the hotspot" is read from the iPhone hotspot's address range (172.20.10.0/28). Name in `hotspot.json`, password only in the login Keychain (`security`, service "Squeak hotspot"); phone command kind `hotspot`; the Mac app's Settings sets it up through the token-gated `POST /control/hotspot` (both end in `applyHotspot`; `clear` removes the Keychain item; the password is never echoed, logged or in `/state`)
- `src/fleet/git-state.ts` — cached working-tree reads, so "finished" says what changed
- `src/fleet/diff-view.ts` — reads and paginates a workspace diff for review in Telegram
- `src/fleet/duck-mood.ts` — what the duck is doing, derived where CI can test it
- `src/fleet/claude-pricing.ts` — per-token dollar rates; a model missing here returns null, never a guess
- `src/fleet/claude-cost.ts` — whole-file, cached, lazy Claude cost estimate — see the note below on why
- `src/workflows/types.ts` — the opaque core shapes (`WorkflowStatus`: provider, projectDir, title, revision, since, prompt; `WorkflowProgress`) a session carries while a product waits on the person; which product and how it is answered belong to the add-on that annotates it (`AddonHandle.sessionAnnotators`)
- `addons/rasanai/` — **RasanAI, a distributed add-on** (`distributed: true`: in every build, inert until enabled in Settings › Extensions; start state is OFF for everyone, no migration enables it). A RasanAI film's director is a Claude session whose cwd has `.rasanai/current`; `provider.ts`/`run.ts` read `session.json` (Studio's rule, ignored after 24 h), the newest session in the folder pages as `awaiting_input`, and the phone's `workflow` card answers through RasanAI's file protocol (`actions.jsonl` under `actions.lock`, `source: "squeak-phone"`), checked against the file as it is then. Only runs whose `console.json` says `external_actions: 1` (RasanAI's `references/remote.md`), or, before that contract, headless Studio runs. Never the console's HTTP server. `films.ts`, `director.ts`: films independent of chats (the phone's `films`, caps `films`; `film` commands answer/chat/resume/stop/installTool; liveness from `director-events.jsonl` + pid; `director.mjs` (RasanAI 1.28+) only from an engine under an install root, never the film's own folder; `external_actions` 1 and 2). `phone.ts`: the add-on's side of the phone channel through `AddonHandle` (`sessionAnnotators`, `phoneViewFields`, `phoneSessionFields`, `phoneCommands` `workflow` and `film`, `phoneImages`, `phoneMedia`); core has verified signature, expiry, nonce and size before a handler runs, and only while enabled, so a handler checks what only it knows (the session is in the Mac's own snapshot and still waiting, step/revision against the files, `FILM_ID`, listed films, the 20 s throttle). `phone-media.ts` makes the phone copy (RasanAI's own `proxy`, else `avconvert` WiFi preset / `afconvert` AAC, cached); core owns the upload: sealed 384 KB chunks under the channel's `media` kind, Realtime Database only, deleted after 30 min (`remote-media.json` ledger, swept at start), a chunk write gets 90 s. The animatic and the film are reviewed on the phone (`review`). Design: `docs/rasanai-plugin.md`; `addons/rasanai/README.md`
- `src/remote/` — the phone channel's Mac side: crypto, Firestore REST, `RemoteBridge`
- `src/cloud/hosted.ts` — Squeak hosts one relay for everyone and signing in is the setup (`POST /account/macs/provision`, the Mac's own key in `cloud.json`, `hosted` in `/control/cloud` and `/state`, `legacy` = what an old install is on, the signed `move` after sign-in; docs/remote-channel.md, "Squeak hosts the cloud"). The old shared Firebase server (`SQUEAK_REMOTE_SHARED`, `shared-limits.ts`, `firebase/shared/`) is **removed**: a Mac still set for it logs one line at start, keeps its config and reports `legacy: "shared"` until sign-in moves it. Self-hosting routes answer 410
- `src/remote/local-channel.ts`, `mirror-store.ts`, `local-auth.ts` — the direct same-Wi-Fi path to a paired phone: an HMAC-gated LAN server over a mirror of the channel's documents, Bonjour `_squeak._tcp` through `dns-sd`, request/response MACs (docs/remote-channel.md, "The direct path"). `SQUEAK_REMOTE_LOCAL=off` disables it; `fake-rtdb.ts` is an in-memory database for tests and the local e2e
- `src/adapters/claude-code.ts` — spawns `claude`, parses its stream-json output
- `src/adapters/codex-app-server.ts` — JSON-RPC client for the codex app-server
- `addons/conductor/` — **the Conductor add-on, shipped in every build, inert until enabled** (Settings › Extensions; `conductor` in `addons.json`). Everything that knows Conductor: `registry.ts` (all reads/writes against `conductor.db`, opened lazily), `observer.ts`, `replier.ts` (window typing, then background CLI), `mirror.ts`, `ui.ts`, `close-chat.ts`, `new-chat.ts`, `chat-models.ts`, `answer.ts`, `project-icons.ts`, `tabs.ts`, `relay-retire.ts` (puts Conductor back from the old relay; its maintenance hook runs at every start even when disabled), `picks.ts` (workspace picks in `<support dir>/conductor/workspaces.json`, starting empty), `import-conductor`/`move-from-conductor` as `squeak` CLI commands. Core wire fields (`conductorSessionId`, `conductorWorkspaceId`, `/state.conductorLinked`) are still produced for old Mac and phone apps
- `src/telegram/client.ts` — Telegram API calls, HTML rendering, retry/fallback
- `src/voice/` — phone calls through a SIP extension (3CX free works): rings the owner when an agent waits on them, reads the question, a PIN then a key answers it. `baresip` per call over `ctrl_tcp`, files for audio; the call is placed by a Home Assistant add-on (`homeassistant/squeak-voice/`, `gateway.ts`, sealed+signed requests over the Realtime Database `voice`/`voiceresult` kinds) or directly by the Mac; calling in (`inbound-flow.ts`, `sip-phone.ts`, Mac `memo-inbox.ts` with Whisper). `squeak voice-relay`, `voice-gateway`, `voice-test`. Read `docs/voice.md`
- `src/voice/voice-engines.ts` — the call voice's engines (Kokoro, and Qwen3-TTS, Ming, Chatterbox on mlx-audio: own folder, venv, weights, voices; one worker for an MLX engine), with `voice-mood.ts` (`moodOf`) and `natural-worker-mlx.ts` (the MLX Python workers); setup reuses weights already in the Hugging Face cache. Read `docs/voice.md`, "Voice engines"
- `src/cliq/` — Zoho Cliq: cards out through the bot's `/message` endpoint (not `/incoming`, which answers 200 and shows nothing); taps and replies back through HMAC-signed records the bot's Deluge handlers post to a Firestore relay, because a managed Zoho org blocks the Mac's own OAuth (`oauth_app_blocked`). Read `docs/cliq.md` first
- `src/telegram/avatar.ts` — sets the Telegram bot's photo to Squeak's logo: `setMyProfilePhoto` (Bot API 9.4: multipart, `photo` = `{type:"static",photo:"attach://…"}`, a **JPG** only) with `brand/logo/png/squeak-bot-avatar-640.jpg` (the duck at 65% on Ink; `embed-daemon.sh` copies that one file to `daemon/brand/logo/png`, found two folders above `dist/telegram`); `POST /control/telegram/avatar`, the phone's signed `telegramAvatar` command and view flag `telegramAvatar` end in one `TelegramAvatar.apply` (one try per 30 s, fixed sentences; docs/remote-channel.md, "Telegram avatar"). Cliq has no API for it: docs/cliq.md
- `src/utils/tg-format.ts` — markdown to Telegram HTML, message splitting
- `macos/` — **Squeak for Mac**, the live Mac app: native SwiftUI menu-bar app (SwiftPM; `swift test`, `macos/scripts/build-app.sh`, `release.sh`, Sparkle updates, bundle id `com.squeak.mac`, installed at `/Applications/Squeak.app`). Reads Conductor's database itself, talks to the daemon's control routes, owns the menu-bar panel, conversation window, quick composer, Settings. Read `macos/README.md`
- `helpers/squeak-decider/` + `src/native/on-device.ts` — the on-device decider: a SwiftPM helper (`embed` = NaturalLanguage sentence embeddings, `decide` = FoundationModels; JSON on stdin/stdout; tests: `cd helpers/squeak-decider && swift test`) bundled at `Contents/Helpers/squeak-decider`. The host spawns it per request (4 s embed, 8 s decide, never blocks); missing, unavailable (Apple Intelligence off, paused 5 min) or broken falls back to TF-IDF similarity and Haiku. Setting `deciderModel` `"on-device"` (default) or `"haiku"` in `agent-settings.json` (Settings › Agents › Messages › Routing), read on every Task. `SQUEAK_DECIDER_BIN` overrides the path
- `helpers/squeak-hands/` — the signed Swift helper that alone holds the Accessibility grant
- `ios/` — Squeak for iPhone (SwiftUI, xcodegen) and `SqueakCore` (`swift test`)
- `scripts/addons.sh`, `src/fleet/relay-retire.ts` — `scripts/addons.sh build|check` compiles/type-checks whatever is in `addons/` (`npm run build` and `typecheck` call it; lint, prettier and vitest pick the folder up when present). `macos/scripts/embed-daemon.sh` builds from `src/` alone and fails if an add-on is in the bundle or imported. The dev-only Conductor relay add-on (`addons/conductor-relay/`, `macos/Addons/ConductorRelay/`) is **deleted** (it is in git history): `src/fleet/relay-retire.ts` and `addons/conductor/relay-retire.ts` stay in core because they protect installs whose `roundhouse_client_url_override` is still `http://127.0.0.1:<Squeak's port>`: at start `retireStaleRelay` puts Conductor back (backup, override row, Keychain device) and never touches any other override. - `scripts/move-checkout.sh`, `scripts/rename-in-conductor.py` — move the checkout; rename the repo in Conductor's records (Conductor quit) keeping every chat
- `DESIGN.md` — the brand and design system every surface follows; tokens in §11
- `brand/` — the brand kit: logo SVG/PNG and the approved source, the guidelines (PDF and Illustrator master), Figtree/Inter/JetBrains Mono with licences, brand tokens. Rules are in `DESIGN.md`
- `docs/remote-channel.md` — the phone channel's threat model and design — read before touching it
